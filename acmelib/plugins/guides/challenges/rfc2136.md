# RFC 2136 dynamic update - setup for acme

acme proves names by DNS-01 by sending a **dynamic DNS UPDATE** (RFC 2136), signed with a **TSIG key**, straight to the zone's primary name server - BIND, Knot, PowerDNS, or Windows DNS (unsigned only). acme writes and signs the UPDATE itself (no `nsupdate` needed): it adds a TXT value at `_acme-challenge.NAME` and later deletes exactly that value. The zone is found by asking the server (then DNS) for the SOA, unless set.

## What you need

- The zone's **primary** (the server that accepts updates) reachable from acme on **TCP/UDP 53**.
- A TSIG key (`hmac-sha256` recommended; `hmac-sha512/-384/-224`, `hmac-sha1`, `hmac-md5` also work) that the server lets update TXT records.
- A dynamic zone (BIND keeps a `.jnl` journal next to the zone file - the directory must be writable by `named`).

## Set up the DNS server

**BIND 9:**

```sh
tsig-keygen -a hmac-sha256 acme-key > /etc/bind/acme-key.conf
```

In `named.conf`:

```text
include "/etc/bind/acme-key.conf";
zone "example.com" {
    type primary; file "/var/lib/bind/example.com.zone";
    update-policy { grant acme-key zonesub TXT; };   # TXT records only, anywhere in the zone
};
```

Tighter: `grant acme-key subdomain _acme-challenge.example.com. TXT;` per name (or `name` for exact labels). Then `rndc reconfig`.

**Knot DNS:** add the key under `key:` and an ACL `acl: [{id: acme, key: acme-key, action: update, update-type: [TXT]}]`, referenced by the zone (`acl: acme`).

**PowerDNS:** `dnsupdate=yes` in `pdns.conf`; import the key and allow it on the zone:

```sh
pdnsutil import-tsig-key acme-key hmac-sha256 'BASE64SECRET'
pdnsutil set-meta example.com TSIG-ALLOW-DNSUPDATE acme-key
```

**Windows DNS:** signs updates only with GSS-TSIG (Kerberos), which acme does not speak. Either use the `windows_dns` / `ssh_dns` validations, or set the zone to **Nonsecure and secure** dynamic updates, restrict who may reach port 53 to acme's address, and leave the key empty.

## Fill in acme

| acme field | What to put there |
|---|---|
| Primary server | `ns1.example.com:53` - the primary, port 53 unless said |
| Zone | empty (found by SOA), or the zone - set it so *Test* can try the key |
| TSIG key name | `acme-key` - exactly as in the server's key statement; empty = unsigned |
| TSIG algorithm | `hmac-sha256` (as the key was made) |
| TSIG secret | the base64 `secret "..."` of the key |
| TTL (s) | 60 (advanced) |
| Sent over | TCP (default) or UDP (advanced) |

## Check it

- In acme press **Test**: with *Zone* set it sends an UPDATE whose only content is the prerequisite "the zone's SOA exists" - the key, the zone and the permission are tried and **nothing is changed**.
- The same by hand:

```sh
nsupdate -y hmac-sha256:acme-key:BASE64SECRET <<'EOF'
server ns1.example.com
zone example.com
prereq yxrrset example.com SOA
send
EOF
```

## Common problems

| Problem | Fix |
|---|---|
| REFUSED | The key is not allowed: `update-policy` / `allow-update` (BIND), the ACL (Knot), `TSIG-ALLOW-DNSUPDATE` (PowerDNS), "Dynamic updates" (Windows). |
| NOTAUTH | The server is not the zone's primary, or it does not know the key (name or algorithm differ). |
| BADTIME / TSIG error | acme's and the server's clocks differ by more than 5 minutes. |
| SERVFAIL | The server could not apply it - often it cannot write its journal; see its log. |
| NOTIMP | The server takes no dynamic updates (a secondary, or a static zone). |
