# Dynamická aktualizace RFC 2136 - nastavení pro acme

acme prokazuje jména metodou DNS-01 tak, že pošle **dynamický DNS UPDATE** (RFC 2136) podepsaný **klíčem TSIG** přímo primárnímu jmennému serveru zóny - BIND, Knot, PowerDNS, nebo Windows DNS (jen nepodepsaně). acme UPDATE sestaví a podepíše sám (`nsupdate` není potřeba): přidá TXT hodnotu na `_acme-challenge.JMÉNO` a později smaže přesně tuto hodnotu. Zónu najde dotazem na SOA u serveru (pak v DNS), není-li zadána.

## Co potřebujete

- **Primární** server zóny (ten, který přijímá aktualizace) dostupný z acme na **TCP/UDP 53**.
- Klíč TSIG (doporučeno `hmac-sha256`; fungují i `hmac-sha512/-384/-224`, `hmac-sha1`, `hmac-md5`), kterým server dovolí měnit TXT záznamy.
- Dynamickou zónu (BIND vede žurnál `.jnl` vedle souboru zóny - adresář musí být zapisovatelný pro `named`).

## Nastavení DNS serveru

**BIND 9:**

```sh
tsig-keygen -a hmac-sha256 acme-key > /etc/bind/acme-key.conf
```

V `named.conf`:

```text
include "/etc/bind/acme-key.conf";
zone "example.com" {
    type primary; file "/var/lib/bind/example.com.zone";
    update-policy { grant acme-key zonesub TXT; };   # jen TXT záznamy, kdekoli v zóně
};
```

Úžeji: `grant acme-key subdomain _acme-challenge.example.com. TXT;` pro každé jméno (nebo `name` pro přesná návěští). Pak `rndc reconfig`.

**Knot DNS:** přidejte klíč do `key:` a ACL `acl: [{id: acme, key: acme-key, action: update, update-type: [TXT]}]`, na které zóna odkazuje (`acl: acme`).

**PowerDNS:** `dnsupdate=yes` v `pdns.conf`; importujte klíč a povolte ho na zóně:

```sh
pdnsutil import-tsig-key acme-key hmac-sha256 'BASE64SECRET'
pdnsutil set-meta example.com TSIG-ALLOW-DNSUPDATE acme-key
```

**Windows DNS:** podepisuje aktualizace jen přes GSS-TSIG (Kerberos), který acme neumí. Použijte validace `windows_dns` / `ssh_dns`, nebo zóně nastavte dynamické aktualizace **Nonsecure and secure**, přístup na port 53 omezte na adresu acme a klíč nechte prázdný.

## Vyplnění v acme

| Pole v acme | Co zadat |
|---|---|
| Primary server | `ns1.example.com:53` - primární server, port 53, není-li uveden |
| Zone | prázdné (dohledá se přes SOA), nebo zóna - vyplňte, aby *Test* mohl klíč vyzkoušet |
| TSIG key name | `acme-key` - přesně jako v deklaraci klíče na serveru; prázdné = nepodepsáno |
| TSIG algorithm | `hmac-sha256` (podle toho, jak byl klíč vytvořen) |
| TSIG secret | base64 `secret "..."` klíče |
| TTL (s) | 60 (pokročilé) |
| Sent over | TCP (výchozí) nebo UDP (pokročilé) |

## Ověření

- V acme stiskněte **Test**: s vyplněnou *Zone* pošle UPDATE, jehož jediným obsahem je předpoklad „SOA zóny existuje“ - vyzkouší se klíč, zóna i oprávnění a **nic se nezmění**.
- Totéž ručně:

```sh
nsupdate -y hmac-sha256:acme-key:BASE64SECRET <<'EOF'
server ns1.example.com
zone example.com
prereq yxrrset example.com SOA
send
EOF
```

## Časté problémy

| Problém | Řešení |
|---|---|
| REFUSED | Klíč není povolen: `update-policy` / `allow-update` (BIND), ACL (Knot), `TSIG-ALLOW-DNSUPDATE` (PowerDNS), „Dynamic updates“ (Windows). |
| NOTAUTH | Server není primárním serverem zóny, nebo klíč nezná (liší se jméno nebo algoritmus). |
| BADTIME / chyba TSIG | Hodiny acme a serveru se liší o víc než 5 minut. |
| SERVFAIL | Server změnu nemohl provést - často nemůže zapsat žurnál; viz jeho log. |
| NOTIMP | Server nepřijímá dynamické aktualizace (sekundární server nebo statická zóna). |
