# A10 Thunder / vThunder - setup for acme

acme signs in to the device through **aXAPI v3** (`POST /axapi/v3/auth`), imports the
certificate and its key as SSL files under a dated name (`acme-<name>-<date>-<serial>`),
imports the intermediates once as a chain file `acme-ca-<id>`, points the client-SSL
templates you list at them, takes the older acme entry out of each template, runs
`write memory` (when asked) and deletes older acme files beyond *keep*. It signs off at
the end.

For ACOS 4.1 and later (checked against the aXAPI schemas of ACOS 5.2.1 and 7.0.3) on
Thunder hardware, vThunder and Thunder in the cloud.

## What you need

- ACOS 4.1 or later with aXAPI v3 (the HTTPS management interface).
- Network access from acme to the management address, **TCP 443** (or your HTTPS port).
- The client-SSL templates that should use the certificate already exist (acme does not
  create templates or virtual servers).
- If the templates live in an L3V partition: its name.

## Set up A10 Thunder

1. Make sure HTTPS management is enabled on the interface acme reaches (management
   interface or a data interface with `enable-management service https`).
2. Create a dedicated admin account for acme with **write** privilege and **aXAPI** access
   (it imports files, changes templates and writes memory - read-only is not enough).
   For a partition, a partition-write privilege for that partition is enough.

   ```text
   configure
   admin acme password <strong-password>
     privilege write
     access axapi
   exit
   write memory
   ```

   The exact sub-commands differ between ACOS releases (for example
   `privilege partition-write` and the partition to bind) - check `admin ?` on your
   version. Keep `access cli`/`web` off if you do not need them.
3. Optionally restrict who may reach the management interface (management access
   lists) and allow the acme server's IP address there.
4. Note the client-SSL template names (`show slb template client-ssl`).

## Fill in acme

| acme field | What to put there |
|---|---|
| Address | Management IP or DNS name of the device |
| HTTPS port | `443` unless management HTTPS runs elsewhere |
| User | The account from step 2 (default `admin` - better a dedicated one) |
| Password | Its password |
| Partition | `shared`, or the name of the L3V partition of the templates and files |
| Check the device's certificate | On; off only while the device still has its self-signed certificate |
| CA certificate (advanced) | The CA of the device's own management certificate, when not public |
| Client-SSL templates (deploy) | One template name a line, for example `tpl-www-clientssl` |
| Write the configuration (deploy) | On: `write memory` after the change, so it survives a reboot |
| Previous versions to keep (advanced) | How many older acme certificate files to keep (default 1, `-1` keeps all) |
| Check what is served | `www.example.com:443` - the VIP to check after deploying |

## Check it

- Press **Try** on the target: acme signs in, reads the ACOS version and counts the SSL
  certificate files (`signed in to ..., ACOS x.y; N SSL certificate files`).
- On the device after a deployment:

  ```text
  show pki cert
  show running-config slb template client-ssl <template>
  ```

## Common problems

| Problem | Fix |
|---|---|
| `ACOS gave no signature on signing in` / 401 | Wrong user or password, or the account has no aXAPI access |
| `ACOS said ... privilege` | The account is read-only or bound to another partition - give it write privilege |
| Switching to the partition fails | Wrong partition name, or the user may not use that partition |
| Template not found | The template name is misspelt or lives in another partition |
| `the older ... stays (still used?)` | ACOS refuses to delete a file still referenced; it goes on a later run once unused |
| TLS error on connecting | The device has its self-signed certificate: add its CA or turn the check off |
| Change lost after reboot | Turn on *Write the configuration* |
