# F5 BIG-IP - nastavení pro acme

acme pracuje přes **iControl REST**:

1. přihlásí se na `/mgmt/shared/authn/login` a používá token (na konci ho smaže);
2. nahraje klíč a certifikát (`/mgmt/shared/file-transfer/uploads/`) a nainstaluje je jako
   `sys crypto key` / `sys crypto cert` `/<partition>/acme-<jméno>-<datum>-<sériové číslo>`;
3. řetězec nainstaluje jednou jako samostatný certifikát `acme-chain-<id>`;
4. v každém zadaném **client-ssl profilu** nahradí položku cert-key-chain, která držela
   starší certifikát acme (jinak `default`, jinak první); ostatní položky zůstanou;
5. smaže starší certifikáty a klíče acme nad počet *ponechat* (používaný zůstane);
6. `save sys config` a se *Sync to device group* `config-sync to-group`.

Duální certifikát (ECDSA + RSA) dá každému profilu dvě položky cert-key-chain, od každého
druhu jednu.

Pro BIG-IP LTM (TMOS) 13.x a novější, hardware, VE i cloudové edice.

## Co potřebujete

- Správcovskou adresu BIG-IP (management port nebo self IP s povolenou správou HTTPS),
  **TCP 443**, dostupnou z acme.
- Uživatele, který smí používat iControl REST, spravovat klíče/certifikáty **i** client-ssl
  profily a ukládat konfiguraci.
- V HA páru: jméno device group pro config-sync.

## Nastavení BIG-IP

1. Vytvořte pro acme lokálního uživatele. Role *Certificate Manager* umí spravovat klíče a
   certifikáty, ale **ne profily**; pro profily a ukládání použijte **Administrator** na
   oddílu (nebo *Resource Administrator*). Přes `tmsh`:

   ```text
   tmsh create auth user acme password <silne-heslo> partition-access add { Common { role admin } } shell none
   tmsh save sys config
   ```

   (GUI: **System → Users → User List → Create**, *Role*: Administrator, *Partition
   Access*: oddíl, *Terminal Access*: Disabled.)
2. Omezujete-li přístup ke správě (**System → Platform → Admin IP / httpd allow list**),
   povolte adresu serveru acme:

   ```text
   tmsh modify sys httpd allow add { 198.51.100.10 }
   ```

3. Se vzdálenou autentizací (LDAP, RADIUS, TACACS+): v acme použijte jméno jejího login
   provideru a účtu acme přiřaďte výše uvedené role.
4. Poznamenejte si client-ssl profily (**Local Traffic → Profiles → SSL → Client**), např.
   `/Common/www_clientssl`, a v HA páru device group (**Device Management → Device
   Groups**).

## Vyplnění v acme

| Pole v acme | Co vyplnit |
|---|---|
| Address / HTTPS port | Správcovská adresa, např. `bigip.example.local` / `443` |
| User | Uživatel z kroku 1 (výchozí `acme`) |
| Password | Jeho heslo |
| Login provider (pokročilé) | `tmos` pro lokální uživatele; jinak jméno provideru vzdálené autentizace |
| Partition | Výchozí `Common` |
| Sync to device group (pokročilé) | např. `dg-failover`; prázdné: bez synchronizace |
| Check the device's certificate / CA certificate | Vypnout jen dokud má BIG-IP self-signed certifikát |
| Client SSL profiles (nasazení) | Jeden na řádek, např. `/Common/www_clientssl` |
| Make missing profiles (nasazení, pokročilé) | Nenalezený profil se vytvoří s rodičem `clientssl` |
| Partition (nasazení, pokročilé) | Prázdné: oddíl cíle |
| Previous versions to keep (pokročilé) | Výchozí 2 |
| Check what is served | Virtuální server, např. `vip.example.com:443` |

## Ověření

- **Try**: `signed in to ..., BIG-IP 17.1.x`.
- Na BIG-IP:

  ```text
  tmsh list sys crypto cert one-line | grep acme-
  tmsh list ltm profile client-ssl www_clientssl cert-key-chain
  tmsh show cm sync-status
  ```

## Časté problémy

| Problém | Řešení |
|---|---|
| 401 při přihlášení | Chybný uživatel/heslo nebo login provider (`tmos` pro lokální uživatele) |
| 403 / `not authorized` u profilů | Role je Certificate Manager - použijte Administrator na oddílu |
| Profil nenalezen | Zadejte celou cestu `/Partition/jmeno`, nebo zapněte *Make missing profiles* |
| Starší certifikát se nesmazal | Ještě ho používá profil; smaže se později |
| Druhá jednotka má starý certifikát | Nastavte *Sync to device group*, ověřte `tmsh show cm sync-status` |
| Profil odmítne druhý klíč stejného druhu (duální) | Odeberte jinou položku toho druhu, která nepatří acme |
